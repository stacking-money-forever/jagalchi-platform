# Jagalchi UX Redesign 방향성 제안서 (Design Directions)

- **작성일자:** 2026-09-07
- **작성 주체:** Gemini Design-Direction Stage
- **대상 저장소:** `jagalchi-platform/ux-redesign`
- **산출물 경로:** `design/redesign-v2/GEMINI-DIRECTIONS.md`

---

## 1. 개요 및 설계 원칙

본 문서는 `design/redesign-v2/FORENSICS.md` 및 `design/redesign-v2/PRESERVE-KILL-QUESTION.md`의 문제 진단을 바탕으로, Jagalchi 제품의 정보 구조(IA), 레이아웃, 시각적 톤을 전면 재정의하는 세 가지 구조적 방향성을 제시합니다.

### 불변의 전제 및 제약 조건
1. **제품 약속 (Core Promise):** 사용자가 목표 직무/공고에 맞춘 하나의 프로젝트를 선택하고, 다음 유의미한 작업(Next Action)을 수행하며, 검증된 결과를 이해하고, 원하는 형태로 Proof를 공유한다.
2. **비즈니스/엔지니어링 무결성:** 백엔드 API 계약(`@jagalchi/api-client`), 상태 머신 가드, 멱등성 보장, 픽스처 정직성(Fixture Honesty), React Flow 엔진은 그대로 보존한다.
3. **사용자 중심 언어:** 내부 엔지니어링 용어(내부 UUID, 프로젝션 버전, provenance, 내부 상태 머신 enum)를 기본 UI 계층에서 제거하고 일상적이고 명확한 제품 언어로 치환한다.
4. **안락한 다크 모드 (Comfortable Dark Mode):** 극단적인 순수 블랙(#000000) 콘솔 룩을 지양하고, 따뜻하고 밝은 톤의 레이어드 차콜(#121316 ~ #22252e)과 명확한 시맨틱 상태 색상을 적용한다.
5. **장식 배제:** 불필요한 글래스모피즘(glassmorphism), 컨페티 애니메이션, 허위 대시보드 지표, 과도한 전환 효과를 전면 금지한다.

## 2. 세 가지 구조적 방향성 (Three Structural Directions)

---

### 방향성 A: 단일 여정 워크스페이스 (Single Journey Workspace)
> **"Focus와 Map이 공존하는 마스터-디테일 적응형 작업 공간"**

#### 1. Thesis (핵심 명제)
기존의 4개 분절 탭(지도/선형/포커스/Proof)을 단일 통합 화면으로 해체한다. 사용자가 현재 실행해야 하는 **'Next Action Hero'**와 전체 진행 맥락을 보여주는 **'React Flow 여정 트랙(Journey Track)'**이 상시 동기화되어, 탭을 오가지 않고도 캔버스와 작업 패널 간의 자연스러운 조작이 이루어지는 구조다.

#### 2. Home (`/myroadmap`)
- **Hero 영역 (Active Project Focus):** 사용자가 현재 진행 중인 최우선 프로젝트 카드를 상단에 대형으로 배치. "다음 작업: [태스크명] 바로가기" 단일 1-Click CTA 제공.
- **프로젝트 목록 (Clean Run Cards):** 하단에 최근 프로젝트 목록을 카드 그리드로 제공. 불필요한 레거시 빈 로드맵/디렉토리 그리드는 완전히 제거.
- **상태 요약:** 완료된 마일스톤 비율(예: 3/5 완료), 최종 검증 상태, 연결된 GitHub 레포지토리 정보를 직관적인 배지로 노출.

#### 3. Create Flow (`/projects/new`)
- **3단계 가이드 여정 (Goal → Diff → Launch):** 11단계 내부 상태 머신을 백그라운드로 캡슐화하고 사용자에게는 명확한 3단계로 제공.
  1. *목표 정의:* 공고 URL 입력 또는 직무 텍스트 입력
  2. *역량 차이 & 프로젝트 비교:* AI 분석 결과 요약 카드 및 추천 프로젝트 2~3개 비교 선택
  3. *저장소 연결 & 시작:* GitHub 저장소 모드(신규 생성/기존 연결/포크) 선택 후 '프로젝트 시작' 확정
- 비동기 분석 폴링은 인라인 프로그레스 바로 처리되어 화면이 튕기거나 모달이 난립하지 않음.

#### 4. Project Detail (`/projects/[runId]`)
- **공통 AppShell 일관 유지:** 제품 헤더와 네비게이션이 유지된 상태에서 2열 분할(Split) 또는 마스터-디테일 레이아웃 적용.
- **좌측/중앙 (Roadmap Canvas):** React Flow 기반 여정 트랙.
- **우측 고정/슬라이드 (Action Execution Panel):**
  - 상단: 현재 선택/추천된 태스크의 핵심 목표 및 가이드
  - 중단: 실행 체크리스트 및 가이드 코드/명령어
  - 하단: "검증 실행 (Verify)" 단일 주요 액션 버튼 및 최근 검증 로그

#### 5. React Flow Roadmap (여정 트랙 캔버스)
- **노드 조판:** 기술적 블록이 아닌 **'마일스톤 스테이지 카드'**. 각 노드는 단계 번호, 작업명, 상태 아이콘(대기/진행/완료/검증중), 예상 시간을 표시.
- **경로 가시화:** 현재 활성 경로(Current Path)는 굵고 선명한 브랜드 컬러 라인으로 연결. 이전 완료 노드는 축소된 체크포인트 배지로 간소화, 미래 잠금 노드는 반투명 처리.
- **인터랙션:** 노드 클릭 시 우측 액션 패널의 내용이 즉시 해당 태스크로 동기화되며 캔버스가 부드럽게 중앙 정렬.

#### 6. Proof / Share
- 프로젝트 로드맵의 최종 도달점(Final Milestone Node)에 'Proof 발급 및 공유' 노드가 위치.
- 모든 필수 태스크 검증이 완료되면 우측 패널이 'Proof 리포트 모드'로 전환되어 획득한 역량 증명, 검증된 PR 목록을 보여주고 '공개 링크 복사' 및 '공개 프로필 발행' 토글을 제공.

#### 7. Desktop & Mobile Behavior
- **Desktop (1024px+):** 좌측 60% React Flow 캔버스 + 우측 40% 고정 액션 패널.
- **Tablet/Mobile (<1024px):** 상단에 콤팩트 Next Action 바 고정, 메인 영역은 세로 스크롤형 인터랙티브 로드맵 타임라인(또는 바텀시트 결합 캔버스)으로 전환.

#### 8. Dark Mode Tone
- **배경 (Background):** `#111215` (따뜻한 다크 차콜)
- **서피스 (Surface / Cards):** `#181a20` (카드), `#22252e` (액션 패널 및 활성 노드)
- **보더 (Border):** `#2c303b`
- **텍스트 (Foreground):** `#f3f4f6` (Primary), `#9ca3af` (Secondary)
- **시맨틱 악센트:** 성공 `#22c55e`, 진행/강조 `#3b82f6`, 경고 `#f59e0b`, 오류 `#ef4444`

#### 9. Component Anatomy
- `ProjectRunWorkspace`: 2열 Split 컨테이너
- `NextActionHero`: 현재 수행할 작업, 검증 버튼, 가이드 힌트를 담는 고밀도 카드
- `JourneyMapCanvas`: React Flow 기반 스테이지 노드 렌더러
- `TaskDetailDrawer`: 선택된 태스크의 검증 상세 및 아티팩트 뷰어

#### 10. Navigation
- 상단 글로벌 헤더: 로고, 내 프로젝트(`myroadmap`), 프로젝트 시작(`projects/new`), 프로필/설정.
- 프로젝트 내부: 별도 하위 탭 없이 캔버스 노드 클릭이 곧 딥링크 네비게이션.

#### 11. User Action Hierarchy
1. *Primary (최우선):* '검증 실행하기' / '작업 완료하고 다음 단계로'
2. *Secondary (보조):* '가이드 보기', 'GitHub PR 확인'
3. *Tertiary (도구):* '캔버스 화면 맞춤(Fit View)', '보관하기'

#### 12. Accessibility (접근성)
- React Flow 캔버스 외에 `Tab` 키로 모든 노드를 순차 탐색 가능한 키보드 포커스 링 제공.
- 상태 표시는 색상뿐 아니라 텍스트 레이블("완료됨", "진행 중", "잠김")과 `aria-current="step"`을 병기.

#### 13. Preserved & Removed Elements
- **Preserved:** React Flow 엔진, 검증 API 통신, 픽스처 로직, 실시간 폴링.
- **Removed:** 4개 분절 탭(지도/선형/포커스/Proof), 레거시 로드맵 그리드, 원시 ID 노출.

#### 14. Risks
- 캔버스와 액션 패널의 상태 동기화 복잡도 증가.

#### 15. Implementation Cost
- **중간 (Medium):** 기존 React Flow 컴포넌트와 Focus 뷰 로직을 마스터-디테일 구조로 재조합하므로 재사용성이 높음.

### 방향성 B: 작업 스트림 우선 & 공간 맵 확장 (Task-Stream Led with Spatial Map Expand)
> **"일상적 선형 실행에 집중하고, 전체 구조는 필요 시 모달/확장 캔버스로 조망"**

#### 1. Thesis (핵심 명제)
대다수 개발 사용자는 일상적인 실행 시 '위계적 그래프'보다 '정리된 작업 목록과 터미널형 검증 체크리스트'에서 인지 부하를 덜 느낀다. 따라서 기본 작업 인터페이스를 **'선형 태스크 스트림(Linear Task Stream)'**으로 두고, 전체 프로젝트 경로와 분기 관계를 조망할 때만 React Flow 기반의 **'공간 맵(Spatial Map)'을 전체 화면/오버레이로 확장**하여 탐색하는 구조다.

#### 2. Home (`/myroadmap`)
- **태스크 피드형 대시보드:** "오늘 진행해야 할 작업" 섹션이 상단에 노출되고, 사용자가 속한 프로젝트들이 아코디언 형태의 태스크 목록으로 나열.
- 각 프로젝트 행을 누르면 인라인으로 다음 태스크와 상태가 펼쳐짐.

#### 3. Create Flow (`/projects/new`)
- **선형 설정 폼 (Linear Config Flow):** 상단에 1-2-3 단계 프로그레스가 표시되는 카드 기반 마법사.
- 공고 분석 결과가 목록 형태로 나타나며, 사용자가 체크박스로 습득할 역량을 토글한 후 프로젝트 생성.

#### 4. Project Detail (`/projects/[runId]`)
- **메인 뷰:** 깔끔한 선형 태스크 타임라인. 현재 진행 중인 태스크가 자동으로 확장(Expanded)되어 검증 기준, 코드 스니펫, 검증 상태를 인라인으로 노출.
- **상단 툴바:** "전체 로드맵 맵으로 보기 [지도 아이콘]" 버튼이 눈에 띄게 위치.
- 완료된 태스크는 체크 아이콘과 함께 접히고, 미래 태스크는 잠금 상태로 대기.

#### 5. React Flow Roadmap (공간 맵 오버레이)
- 상단 툴바의 '지도 보기' 버튼을 누르면 전체 화면 오버레이 또는 확장 패널로 React Flow 캔버스가 열림.
- 노드는 마일스톤 간의 선후 관계와 병렬 경로를 명확한 구조도로 시각화.
- 노드를 클릭하면 해당 노드가 선택된 상태로 선형 스트림 메인 뷰로 복귀.

#### 6. Proof / Share
- 선형 태스크 목록의 최하단에 항상 'Proof 검증 완료 카드'가 위치.
- 모든 이전 태스크가 체크되면 활성화되며, 검증 요약과 배지를 확인하고 바로 링크를 공유할 수 있음.

#### 7. Desktop & Mobile Behavior
- **Desktop:** 중앙 정렬된 넓은 단일 컬럼 태스크 스트림(최대 840px). 우측 상단 맵 전환.
- **Mobile:** 모바일 화면에 가장 자연스러움. 상하 스크롤 목록 형태이며, 맵 확장은 핀치-줌이 지원되는 풀스크린 모달로 동작.

#### 8. Dark Mode Tone
- **배경 (Background):** `#141518` (모노톤 다크 그레이)
- **서피스 (Surface):** `#1c1e22` (태스크 블록), `#24272e` (현재 활성 태스크 강조)
- **보더 (Border):** `#2e323b`
- **텍스트 (Foreground):** `#ffffff` (Primary), `#a1a1aa` (Secondary)

#### 9. Component Anatomy
- `TaskStreamList`: 선형 태스크 목록 및 아코디언 확장 컨테이너
- `InlineTaskExecutor`: 태스크 상세 지침, 검증 조건, 실행 버튼이 통합된 인라인 카드
- `RoadmapModalCanvas`: React Flow 기반 전체 구조 조망 오버레이

#### 10. Navigation
- 상단 바: 프로젝트 명, 현재 태스크 상태 배지, [지도 보기] 토글 버튼.
- 복잡한 탭 없이 단일 스트림 스크롤 기반.

#### 11. User Action Hierarchy
1. *Primary:* 현재 열려있는 태스크의 '검증하기(Verify)'
2. *Secondary:* '다음 태스크 펼치기', '전체 지도 보기'
3. *Tertiary:* '태스크 건너뛰기/보류'

#### 12. Accessibility (접근성)
- 완벽한 표준 HTML 목록(`ol`, `li`) 및 아코디언(`details`/`summary` 또는 `aria-expanded`) 구조로 스크린 리더 친화성 최고.

#### 13. Preserved & Removed Elements
- **Preserved:** React Flow(보조 뷰로 유지), 검증 파이프라인.
- **Removed:** 상시 캔버스 분할 뷰, 복잡한 다중 탭 네비게이션.

#### 14. Risks
- React Flow의 시각적 로드맵이라는 Jagalchi 본연의 '여정 캔버스' 정체성이 보조 도구로 약화될 위험.

#### 15. Implementation Cost
- **낮음 (Low):** 선형 뷰 위주의 단순한 레이아웃 구조.

### 방향성 C: 스테이지-게이트 인터랙티브 캔버스 (Stage-Gate Interactive Canvas Hub)
> **"React Flow 캔버스 전체가 제품의 중심 대시보드이자 인터랙티브 허브"**

#### 1. Thesis (핵심 명제)
React Flow 캔버스를 단순한 그래프 뷰어가 아니라 **제품 전체의 무대(Stage)**로 삼는다. 홈에서 프로젝트로 진입하는 순간 캔버스가 열리며, 사용자는 시맨틱 줌(Semantic Zoom)을 통해 마일스톤 수준(Overview)에서 태스크 실행 카드(Deep Focus)로 매끄럽게 확대/축소하며 탐색한다. 노드 자체가 단순 박스가 아닌 '작업 실행 카드(Action Node)' 역할을 수행한다.

#### 2. Home (`/myroadmap`)
- **프로젝트 캔버스 허브:** 전체 뷰포트에 사용자의 진행 중인 프로젝트들이 성단(Cluster)이나 로드맵 보드 형태로 배치.
- 마우스 호버/탭 시 프로젝트 요약이 떠오르고, 더블클릭/선택 시 해당 프로젝트 캔버스로 줌-인 진입.

#### 3. Create Flow (`/projects/new`)
- **캔버스 위 인라인 위저드:** 빈 캔버스 위에 '새 여정 설계' 카드가 생성되고, 직무 입력과 분석 단계가 캔버스 상에서 노드가 단계적으로 연결되며 시각적으로 빌드되는 경험 제공.

#### 4. Project Detail (`/projects/[runId]`)
- **전체 화면 캔버스 (Full-Bleed Canvas):** 헤더 아래 전체 영역이 React Flow 캔버스.
- **플로팅 HUD (Heads-Up Display):**
  - 좌측 상단: 프로젝트 이름 및 목표 직무 정보
  - 우측 상단: 현재 진행률 및 "Next Action으로 이동" 플로팅 버튼
  - 하단 중앙: 미니맵, 줌 컨트롤, 필터

#### 5. React Flow Roadmap (인터랙티브 스테이지 노드)
- **고도화된 커스텀 노드:**
  - *축소 줌 레벨:* 마일스톤 이름과 완료율 프로그레스 바만 심플하게 표시.
  - *표준 줌 레벨:* 각 태스크의 목표, 상태 아이콘, 난이도 표시.
  - *확대 줌 레벨:* 노드 내부에 바로 검증 체크리스트와 '검증 실행' 버튼이 렌더링되어 캔버스 위에서 직접 작업 수행.

#### 6. Proof / Share
- 캔버스의 최종 종착점에 대형 'Proof 트로피/인증 노드'가 배치됨.
- 완료 시 해당 노드가 활성화되며, 클릭 시 캔버스 내에서 직접 공개 증명서 뷰로 확장.

#### 7. Desktop & Mobile Behavior
- **Desktop:** 넓은 캔버스와 마우스 휠/트랙패드를 통한 자유로운 팬 & 줌 탐색.
- **Mobile:** 캔버스 조작의 한계로 인해, 모바일에서는 캔버스 대신 세로형 스테이지 카드 스와이퍼(Carousel / Vertical Accordion)로 전면 대체 레이아웃 제공.

#### 8. Dark Mode Tone
- **배경 (Background):** `#0e1013` (깊은 스페이스 차콜) + 미세한 그리드 닷(`#1f232b`)
- **서피스 (Surface):** `#161920` (기본 노드), `#202531` (활성 포커스 노드)
- **보더 (Border):** `#282e3d`
- **시맨틱 발광:** 활성 노드에 은은한 블루/그린 보더 하이라이트.

#### 9. Component Anatomy
- `FullBleedCanvas`: 전체 화면 캔버스 컨테이너
- `InteractiveStageNode`: 줌 레벨에 따라 컨텐츠 밀도가 가변하는 인터랙티브 React Flow 노드
- `FloatingProjectHUD`: 상단/하단 오버레이 컨트롤 바

#### 10. Navigation
- 캔버스 뷰포트 내 팬/줌 및 HUD의 [Next Step] 버튼 클릭으로 자동 카메라 팬(Pan to Node).

#### 11. User Action Hierarchy
1. *Primary:* 포커스된 캔버스 노드 내 '검증하기'
2. *Secondary:* HUD 'Next Action 바로가기'
3. *Tertiary:* 줌 레벨 조절, 미니맵 토글

#### 12. Accessibility (접근성)
- 캔버스 내비게이션을 어려워하는 사용자를 위해 `Alt + N` (다음 노드 이동), `Alt + P` (이전 노드 이동) 등 전역 단축키 및 선형 목록 모드 토글 필수 제공.

#### 13. Preserved & Removed Elements
- **Preserved:** React Flow 엔진, 핵심 백엔드 계약.
- **Removed:** 정적 페이지 분할 레이아웃, 별도 태스크 상세 페이지.

#### 14. Risks
- 모바일 대응을 위한 별도 뷰 구현 비용이 매우 큼. 캔버스 내 폼/버튼 조작 시 터치/마우스 이벤트 충돌 위험.

#### 15. Implementation Cost
- **높음 (High):** React Flow 시맨틱 줌 노드 및 캔버스 인터랙션 설계 공수가 큼.

## 4. 최종 추천 방향성 및 근거

### 💡 추천: **방향성 A (단일 여정 워크스페이스 - Single Journey Workspace)**

#### 추천 이유
1. **제품 정체성과의 일치:** Jagalchi의 핵심 가치는 단순 투두리스트가 아닌 '목표 역량에 이르는 로드맵 여정의 가시화와 증명'이다. 방향성 B는 로드맵 캔버스가 지나치게 부차적으로 전락하고, 방향성 C는 조작 피로도와 모바일 구현 리스크가 크다. 방향성 A는 사용자가 **"내가 지금 어디에 있고(Map), 다음에 무엇을 해야 하는가(Action)"**를 한 화면에서 가장 완벽하게 인지할 수 있다.
2. **기존 자산의 가장 우아한 재구성:** 기존에 분절되어 있던 `RoadmapMapCanvas`(지도)와 `ProjectRunFocusView`(포커스 실행), `ProjectRunProofView`(증명)의 컴포넌트 로직을 파괴하지 않고, 탭 분기 대신 마스터-디테일의 상호보완 관계로 통합하므로 엔지니어링 리스크가 가장 낮다.
3. **사용자 친화성과 편안함:** 상단 Next Action Hero를 통해 진입 즉시 다음 작업을 수행할 수 있으며, 어두운 차콜 톤 기반의 다크 모드로 장시간 작업 시에도 눈의 피로가 적다.

## 5. 폐기해야 할 현재 가정 (Assumptions That Must Die)

새로운 UX가 성공하기 위해 다음의 7가지 기존 가정을 즉시 폐기합니다:

1. ❌ **"지도, 선형, 포커스, Proof는 대등한 4개의 탭이어야 한다"는 가정:**
   - *이유:* 사용자는 탭을 전환하며 멘탈 모델을 재구성하는 것을 원하지 않는다. 지도는 '맥락'이고, 포커스는 '행동'이며, Proof는 '결과'이므로 하나의 흐름으로 융합되어야 한다.
2. ❌ **"홈 화면에는 생성된 프로젝트 런과 빈 레거시 로드맵 디렉토리가 함께 공존해야 한다"는 가정:**
   - *이유:* 사용자에게 혼란스러운 이중 소유권과 텅 빈 상태를 노출하여 이탈을 유발한다. 레거시 로드맵 그리드는 분리/제거되어야 한다.
3. ❌ **"내부 오퍼레이션 ID, 프로젝션 버전, provenance 등의 엔지니어링 메타데이터를 UI 상단에 노출해야 한다"는 가정:**
   - *이유:* 개발자 디버깅용 정보일 뿐 사용자에게는 인지 노이즈다. 상태 배지와 목표 직무명만 남기고 디버그 정보는 개발자 도구/하단 메타 영역으로 숨긴다.
4. ❌ **"생성 위저드는 11단계 내부 상태 머신 과정을 사용자에게 단계별로 다 보여주어야 한다"는 가정:**
   - *이유:* 사용자는 '목표 입력 → 비교 선택 → 저장소 연결'이라는 3단계 의사결정만 하면 된다. 내부 비동기 폴링 단계는 인라인 피드백으로 감춘다.
5. ❌ **"다크 모드는 순수 블랙(#000000) 콘솔이어야 한다"는 가정:**
   - *이유:* 명암 대비가 지나치게 극단적이어서 눈의 피로를 가중시키고 관리자 콘솔 느낌을 준다. 레이어드 차콜 톤(#121316 ~ #22252e)으로 전환한다.
6. ❌ **"Proof 화면에서 증거 검증과 전역 프로필 수정을 동시에 처리해야 한다"는 가정:**
   - *이유:* 프로젝트 증거(Proof)는 프로젝트의 완결 아티팩트이며, 계정 전역 프로필 편집과 섞이면 책임 경계가 무너진다.
7. ❌ **"React Flow는 단순한 기술적 DAG 그래프 뷰어다"라는 가정:**
   - *이유:* React Flow는 사용자가 자신의 성장을 체감할 수 있는 '스테이지 여정 캔버스(Milestone Journey Canvas)'로 기능해야 한다.

## 6. 방향성 A 수용 기준 (Acceptance Criteria for Direction A)

### 1. 홈 (`/myroadmap`)
- [ ] 진행 중인 활성 프로젝트 런이 있을 경우, 최상단에 **Next Action Hero 카드**(프로젝트명, 현재 태스크명, 1-Click 바로가기 버튼)가 노출되어야 한다.
- [ ] 레거시 빈 로드맵 및 디렉토리 그리드가 홈에서 완전히 제거되고, 사용자가 생성한 프로젝트 런 카드 목록만 간결하게 렌더링되어야 한다.
- [ ] 프로젝트 런 카드에는 마일스톤 완료율(예: 60%), 최종 상태 배지, 대상 직무명이 명확히 표시되어야 한다.

### 2. 생성 흐름 (`/projects/new`)
- [ ] 11단계 내부 상태 머신 번호가 제거되고, 사용자는 **'1. 목표 정의 → 2. 분석 & 프로젝트 선택 → 3. 저장소 연결 & 시작'**의 직관적인 3단계로만 경험해야 한다.
- [ ] 공고 분석 및 프로필 스냅샷 생성 중에는 UI 이탈 없이 인라인 상태 인디케이터로 진행 상태를 안내해야 한다.
- [ ] 추천 프로젝트 비교 화면에서 각 제안의 핵심 역량, 예상 기간, 저장소 모드가 한눈에 비교 가능해야 한다.

### 3. 프로젝트 상세 및 워크스페이스 (`/projects/[runId]`)
- [ ] 상단 4개 탭(지도/선형/포커스/Proof)이 제거되고, 상단 공통 AppShell 아래 **'좌측 여정 캔버스 + 우측 액션 실행 패널'**의 통합 워크스페이스가 렌더링되어야 한다.
- [ ] 상단 헤더에 난해한 UUID 대신 프로젝트 목표명(또는 직무명)과 직관적인 한국어 상태 배지("진행 중", "검증 완료", "대기 중")가 표시되어야 한다.
- [ ] React Flow 캔버스에서 특정 태스크 노드를 클릭하면 우측 액션 패널의 내용이 해당 태스크의 지침/검증 영역으로 즉시 전환되어야 한다.
- [ ] 우측 액션 패널 상단에는 언제나 현재 추천 태스크로 복귀할 수 있는 단축 앵커가 제공되어야 한다.
- [ ] 태스크 검증 실행 버튼 클릭 시 비동기 검증 결과가 액션 패널 내에 성공/실패 사유와 함께 명확히 피드백되어야 한다.

### 4. React Flow 여정 캔버스
- [ ] 노드는 거친 기술적 사각형이 아닌, 단계 번호와 상태 아이콘, 작업명을 포함한 **'마일스톤 스테이지 카드'** 스타일로 렌더링되어야 한다.
- [ ] 현재 진행 중인 경로(Current Path)는 하이라이트 연결선으로 선명하게 표시되고, 완료된 노드는 체크포인트 형태로 안정감 있게 표현되어야 한다.
- [ ] 캔버스는 키보드 방향키 및 탭 키로 노드 간 이동이 가능해야 하며, `Enter` 키로 해당 노드를 우측 패널에 활성화할 수 있어야 한다.

### 5. Proof 및 공유
- [ ] 모든 필수 태스크가 검증 완료되면 로드맵의 최종 Proof 노드가 활성화되며, 우측 패널에서 발행 가능한 Proof 요약 리포트가 노출되어야 한다.
- [ ] 1-Click으로 공개 Proof 링크를 클립보드에 복사할 수 있어야 하며, 공개 프로필 페이지(`/proof/[publicId]`)와 완벽히 연동되어야 한다.

### 6. 다크 모드 및 시각적 품질
- [ ] `#000000` 순수 블랙 배경이 제거되고, 배경 `#111215`, 카드 서피스 `#181a20`, 포커스 서피스 `#22252e`의 계층형 차콜 팔레트가 적용되어야 한다.
- [ ] 모든 텍스트와 보더는 WCAG AA (텍스트 4.5:1 이상) 명도 대비 기준을 충족해야 한다.
- [ ] 글래스모피즘, 불필요한 그라디언트 텍스트, 장식용 파티클/컨페티가 일체 포함되지 않아야 한다.
